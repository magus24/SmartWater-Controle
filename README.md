# SMART WATER CONTROL

Интерактивная карта водоснабжения с ИИ-анализом протечек на основе данных датчиков давления.
Реальная география — **город Кувасой, Узбекистан** (координаты 40.3657, 71.9428).

Проект демонстрирует полный цикл работы системы мониторинга водопроводной сети:
от геоданных труб и датчиков → расчёта давлений → детекции аномалий (Isolation Forest)
→ формирования инцидента с рекомендациями для аварийной службы.

---

## Возможности

- **Карта сети** — 1 895 труб и 1 644 узла, отрисованных на интерактивной карте
- **5 685 датчиков** давления, генерируемых автоматически вдоль трасс труб
- **Симуляция аварий** — генерация аномалии на случайной трубе сети (`random_leak`)
- **ИИ-детекция** — `Isolation Forest` с гибридной логикой (ML + пороговые правила)
- **Страница истории ИИ** — журнал показаний, аномалий и объяснений модели
- **REST API** — полный доступ к состоянию сети, датчиков и инцидентов

## Запуск

```bash
git clone https://github.com/magus24/SmartWater-Controle.git
cd SmartWater-Controle

python -m venv .venv
```

## API

| Метод | Эндпоинт | Описание |
|-------|-----------|----------|
| `GET`  | `/` | Карта водоснабжения (UI) |
| `GET`  | `/ai-history` | Журнал истории ИИ (UI) |
| `GET`  | `/api/network` | Полное состояние сети: узлы, трубы, датчики, инцидент |
| `POST` | `/api/simulate` | Запустить сценарий утечки. Тело: `{"scenario_key": "..."}`, без тела — случайный |
| `POST` | `/api/reset` | Сбросить симуляцию в нормальное состояние |
| `GET`  | `/api/dashboard-stats` | Сводная статистика для дашборда |
| `GET`  | `/api/pressure-history` | Последние 50 записей истории давлений |
| `GET`  | `/api/pressure-history/{pipe_id}` | История давлений по конкретной трубе |
| `GET`  | `/api/anomalies` | Журнал зафиксированных аномалий |

### Пример

```bash
curl -X POST http://127.0.0.1:8000/api/simulate \
  -H "Content-Type: application/json" \
  -d '{"scenario_key": "random_leak"}'
```

## Как работает детекция

1. По сценарию утечки давление у затронутых датчиков падает относительно `baseline_pressure`.
2. Для каждого датчика считается относительное отклонение в процентах.
3. `Isolation Forest`, обученный на исторических «нормальных» записях, даёт оценку аномалии.
4. Финальный вердикт — гибридный: `ML-вердикт OR отклонение > 15%` (правило-подстраховка).
5. Если сработала тревога, `infer_incident()` собирает инцидент:severity, confidence,
   вероятное место утечки (середина полилинии трубы) и список причин.

Если `scikit-learn` не установлен, система не падает — автоматически включается
пороговый fallback-алгоритм.

## Структура проекта

```

```

## Перегенерация геоданных

Трассы труб строятся из CSV с координатами:

```bash
python sqript.py
```

Скрипт читает CSV, группирует точки по `pipe_index` / `line_index`, сортирует по
`point_order` и перезаписывает `generated_pipes.py`.
